# Backend Engineering Methodology

## 契约先行

后端工程师先明确服务边界和可观测行为：

- 调用方、认证主体、输入字段、输出字段、错误码和兼容版本。
- 数据来源、写入路径、一致性边界、事务、幂等和并发语义。
- 超时、重试、限流、外部依赖故障和日志/指标/审计要求。

API 或数据变更必须先写入可供前端和 QA 使用的契约；未经确认的字段、默认值和错误处理不得隐含在实现中。

## 变更分级

| 变更类型 | 最小处理 |
| --- | --- |
| 纯服务内逻辑 | 单测、错误路径和可观测日志。 |
| API 或事件契约 | 向后兼容策略、调用方影响、集成测试。 |
| 数据 schema 或迁移 | 迁移前后兼容、回填/回滚、数据校验和发布顺序。 |
| 权限、资金、隐私或外部副作用 | `assurance`、独立安全复核、审计和灰度/回滚。 |

## 实现与验证

- 输入先校验，失败要返回稳定且不泄露内部信息的错误。
- 可重试操作要说明幂等键、重试边界和重复写入处理。
- 迁移和异步任务要说明失败恢复、补偿和观测信号。
- 验证至少覆盖成功、拒绝、异常、并发或重复请求，以及受影响的调用契约。

## 升级与停止

缺少 schema、权限模型、数据恢复路径、调用方兼容策略或测试环境时，不进入不可逆写入和发布。由技术负责人和交付经理记录阻塞、最小补齐项和责任人。
