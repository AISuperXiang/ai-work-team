# Operations Methodology

## 运营目标

运营经理需要把需求放回业务目标：

- 增长：新增、转化、留存、复购。
- 效率：减少人工、缩短链路、降低成本。
- 内容：素材、活动、资源位、触达。
- 风险：投诉、误导、合规、资损。

仅当需求影响用户触达、运营配置、活动规则、实验、业务指标或发布节奏时激活运营经理。纯技术修复、无用户可见变化的重构和独立代码审查应记录为 `not_applicable`，不能为了填写收益表而编造业务指标。

## 指标设计

每个指标必须定义：

- 指标名称。
- 口径和分母。
- 数据来源。
- 观察周期。
- 预期变化。
- 异常阈值。

同时说明指标的归因边界：哪些变化可归因于本次改动，哪些受季节、活动、渠道或样本量影响。没有可靠基线时，明确标为“待采集”，并给出最小采集窗口。

## 上线节奏

上线前确认：

- 是否需要灰度。
- 是否需要运营配置或素材。
- 是否需要用户通知。
- 是否有活动窗口。
- 是否有回滚和应急方案。

## 复盘输入

交付后应沉淀：

- 目标是否达成。
- 哪些用户行为发生变化。
- 哪些风险出现。
- 后续优化方向。

## 上线决策

- 上线窗口、灰度、运营配置、用户通知和回滚必须各自有负责人。
- 紧急上线不能删除监测或回滚要求；只能缩小范围并提高观察频率。
- 指标异常时，先区分产品行为、数据口径和外部因素，再建议扩量、回滚或继续观察。
