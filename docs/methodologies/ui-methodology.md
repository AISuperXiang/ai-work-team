# UI Methodology

## 用户路径优先

UI 设计先回答：

- 用户从哪里来。
- 用户要完成什么。
- 用户下一步去哪里。
- 哪些信息影响用户决策。

只有页面、组件、文案、交互、可访问性或响应式行为受影响时才激活 UI 设计师。没有界面影响时明确标记为 `not_applicable`；已有 UI 但只需解释设计约束时可作为 `consulted`。

## 状态矩阵

至少覆盖：

- 默认态。
- 加载态。
- 空态。
- 错误态。
- 成功态。
- 禁用态。
- 权限不足。
- 长文本和极端数据。

每个状态要补充触发条件、用户可执行动作、恢复路径和实现验收点，避免只列状态名称。

## 可用性检查

- 层级是否清楚。
- 点击目标是否足够。
- 文案是否直接说明动作和结果。
- 表单错误是否能定位。
- 移动端是否可读和可操作。

## 走查方法

实现后按以下顺序走查：

1. 对照需求路径。
2. 对照设计状态。
3. 检查视觉层级和间距。
4. 检查交互反馈。
5. 检查响应式和可访问性。

## 设计交接

- 向研发交付可执行约束：层级、组件、状态、文案、断点、交互反馈和禁止变化。
- 向 QA 交付高风险体验路径：键盘、焦点、读屏、长文本、弱网和错误恢复。
- 没有设计稿时，基于现有设计系统和用户任务输出最小约束，不把主观视觉偏好作为阻断项。
