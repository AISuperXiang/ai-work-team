# Engineering Methodology

## 先读现状

研发方案前必须先确认：

- 入口文件和调用链。
- 现有组件、工具和服务边界。
- 配置、环境和权限。
- 测试命令和发布路径。

角色边界：

- 技术负责人负责事实收集、方案裁决、风险和发布边界。
- 前端工程师负责客户端行为、界面状态、可访问性和浏览器证据。
- 后端工程师负责接口、数据一致性、权限、可观测性和迁移边界。
- 三者共享事实与验证计划，但实现代码按文件所有权由一个负责人修改。

## 最小可交付切片

将需求拆成：

- 用户可见行为。
- 数据和接口变化。
- 状态和异常处理。
- 验证路径。

优先交付闭环切片，而不是横向铺开半成品。

## 方案评估

每个方案都要说明：

- 变更文件和模块。
- 接口和数据契约。
- 兼容性。
- 风险和回滚。
- 验证命令。

## 实现原则

- 复用现有模式。
- 只改需求相关范围。
- 不隐藏失败。
- 不引入未要求的平台化。
- 对无法验证的路径说明风险。

跨前后端改动必须在编码前固定接口契约、错误语义、联调顺序和回滚关系。只有涉及的工程角色进入 `rolePlan.active`，不得因 workflow 声明了某角色而强制产生无关实现或文档。
