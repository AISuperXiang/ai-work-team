# Engineering Methodology

## 先读现状

研发方案前必须先确认：

- 入口文件和调用链。
- 现有组件、工具和服务边界。
- 配置、环境和权限。
- 测试命令和发布路径。

## 最小可交付切片

将需求拆成：

- 用户可见行为。
- 数据和接口变化。
- 状态和异常处理。
- 验证路径。

优先交付闭环切片，而不是横向铺开半成品。

## 方案评估

每个方案都要说明：

- 变更文件和模块。
- 接口和数据契约。
- 兼容性。
- 风险和回滚。
- 验证命令。

## 实现原则

- 复用现有模式。
- 只改需求相关范围。
- 不隐藏失败。
- 不引入未要求的平台化。
- 对无法验证的路径说明风险。
