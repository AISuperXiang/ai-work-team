# Handoff Contract

角色之间交接必须携带最小信息包，避免下游角色重新猜测上游决策。

## 通用字段

- 背景：当前需求、目标用户、业务目标。
- 当前阶段：阶段名称、负责人、状态。
- 已确认决策：范围、优先级、技术选择、设计取舍。
- 待确认问题：需要用户或其他角色决策的问题。
- 风险：影响、概率、责任角色、缓解方案。
- 产出物：链接或摘要。
- 验证：已运行检查、结果、未验证项。

## 强制交接规则

- 每次阶段切换必须更新 `role-handoff.md`，不能只在对话中口头交接。
- 下游角色开始前必须检查背景、决策、待确认问题、风险、产物和验证是否齐全。
- 缺少会影响范围、实现或测试的字段时，阶段状态为 `blocked`，由交付经理要求上游补齐。
- 交接记录必须能追溯到 workspace 产物、验证证据或用户决策。

## Hybrid 子 Agent 输出契约

混合执行阶段的子 Agent 输出必须包含：

- `结论`：通过、修改后通过、不通过或需用户决策。
- `证据`：引用的代码、文档、命令、截图、数据来源或人工判断依据。
- `风险`：影响、概率、严重级别、缓解动作和责任角色。
- `置信度`：高 / 中 / 低，并说明不确定来源。
- `需决策项`：最多 3 个，需要用户或交付经理裁决的问题。

交付经理只交付汇总后的统一结论；不得把多个角色互相冲突的原始结论直接抛给用户。

## 产品到 UI

- 用户路径和核心任务。
- 信息优先级。
- 状态和边界要求。
- 文案、指标和业务规则。

## 产品到研发

- PRD、验收标准、范围边界。
- 非目标和延期项。
- 权限、异常和业务规则。
- 上线或运营约束。

## UI 到研发

- 页面结构、组件约束和交互行为。
- 状态矩阵。
- 响应式和可访问性要求。
- 走查重点。

## 研发到 QA

- 改动范围和影响面。
- 接口、数据、配置和环境说明。
- 已知风险和回归建议。
- 验证命令和结果。

## QA 到交付

- 测试范围、用例、结果和证据。
- 缺陷状态。
- 未覆盖范围和剩余风险。
- 是否可交付结论。
