# Business Impact Rubric

本文件定义业务影响评分的独立最低线。端到端交付、PRD 完成态、交付摘要和质量评分必须引用本文件；`docs/quality-rubrics.md` 负责总体质量评分，本文件负责业务价值细则。

## 必填输入

PRD 完成态必须包含：

- 目标用户：明确谁受益，不能只写“用户”。
- 用户价值：说明用户任务、痛点或体验收益。
- 业务价值：说明增长、效率、成本、风险或战略收益。
- 价值假设：说明为什么这个需求能产生价值，以及假设如何被验证。
- 指标基线：给出当前值；没有现成数据时必须写明待采集口径和首轮基线来源。
- 收益目标：给出目标变化、观察周期和判断阈值。
- 成本收益比：说明研发成本、运营成本、维护成本和预期回报。
- 数据来源：说明数据系统、日志、人工验收、用户反馈或实验来源。
- 上线后观测方式：说明观察周期、复盘负责人和下一轮决策入口。

## 评分标准

每项 0-5 分：

- 0：没有业务价值内容。
- 1：只有口头描述，没有用户、指标或证据。
- 2：说明了用户或收益，但指标、基线、成本或数据来源缺失。
- 3：目标用户、价值假设和收益目标基本明确，有可执行观测计划。
- 4：指标基线、目标变化、成本收益比、数据来源和复盘计划完整，可进入交付。
- 5：价值假设已被数据、实验、用户反馈或上线观测验证，并形成下一轮决策。

## 阻断规则

以下任一情况不得进入 PRD 完成态或交付态：

- 只描述功能，不说明目标用户和用户价值。
- 没有价值假设、指标基线、收益目标或观测方式。
- 成本收益比缺失，或只写“成本低”“收益高”等不可验证结论。
- 业务影响评分低于 4 分。
- 声称“收益可观测”但没有数据来源、日志、截图、命令结果、用户反馈或人工验收记录。

## 产物映射

| 产物 | 必须包含 |
| --- | --- |
| `prd.md` | 目标用户、用户价值、业务价值、价值假设、指标基线、目标变化、数据来源、成本收益比、上线后复盘计划 |
| `delivery-summary.md` | 价值假设、指标基线、收益目标、成本收益比、上线后观测结果或计划、证据索引 |
| `workflow-status.json` | PRD 和 Delivery 阶段必须包含 `value-gate` 或 `evidence-gate`，完成态 evidence 不得为空 |
| `evidence/README.md` | 支撑业务影响、收益观测或人工验收结论的来源 |

## 证据要求

允许的证据类型：

- 数据来源：埋点、日志、查询结果、实验平台、运营报表。
- 验证命令：测试、构建、脚本输出或可复现命令。
- 人工验收：用户试玩、产品验收、运营确认、QA 记录。
- 截图或录屏：关键路径、指标看板或 UI 走查结果。
- 外部系统链接：PRD、任务、审批、发布、监控或复盘记录。
