# Code Change Standard

## 范围

- 每个改动必须能追溯到需求、缺陷或验收标准。
- 改动前必须在 `rolePlan` 中明确领域工程角色和文件所有权。
- 不做无关重构、格式化或依赖升级。
- 发现无关问题时记录，不顺手修改。

## 风格

- 优先匹配目标仓库既有目录结构、命名、组件和工具。
- 复用现有 helper、组件、schema 和测试方式。
- 注释只写必要的业务或复杂逻辑说明。

## 兼容

- 不破坏现有接口、配置、数据和用户路径。
- 破坏性变更必须有迁移、回滚和发布说明。
- 多端或多 App 代码要评估功能泄漏。

## 验证

- 实现后运行可用的 lint、typecheck、unit、build 或集成测试。
- 无法运行时说明原因、影响和替代检查。
