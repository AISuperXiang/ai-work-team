# Testing Standard

## 测试层级

按风险选择：

- 单元测试：纯逻辑、工具函数、状态转换。
- 集成测试：接口、数据、跨模块契约。
- E2E 或浏览器验证：关键用户路径。
- 手工验证：自动化不可覆盖但必须验收的体验路径。

测试层级由风险而不是测试偏好决定。每个高风险失效条件要记录负责人、最低验证等级、未覆盖影响和下一步采证动作。

## 必测内容

- 正常路径。
- 异常和错误提示。
- 空态和边界数据。
- 权限差异。
- 兼容和回归影响面。

## 记录要求

每次测试记录：

- 命令或步骤。
- 环境。
- 输入数据。
- 结果。
- 失败原因和修复状态。
- 当前 `verificationLevel` 与结论边界。

## 失败处理

测试失败不得忽略。必须判断：

- 是实现缺陷。
- 是测试用例问题。
- 是环境问题。
- 是需求或验收标准不清。
