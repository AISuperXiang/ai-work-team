# Technical Design Standard

技术方案必须包含：

- 背景和目标。
- 当前系统现状。
- 已确认事实、待验证假设和证据来源。
- 方案概述。
- 变更范围。
- 接口和数据契约。
- 角色责任边界和文件所有权。
- 权限、安全和异常处理。
- 兼容性和迁移。
- 测试策略。
- 发布、灰度、回滚。
- 风险和开放问题。

## 约束

- 方案必须基于实际代码或系统事实。
- 必须引用 `rolePlan`，明确前端、后端、QA、UI 或产品为何参与或不适用。
- 不为单次需求引入不必要抽象。
- 每个关键决策都说明取舍原因。
- 风险不能只写“需注意”，必须写影响和缓解。

## 输出格式

优先使用 `assets/templates/technical-design.md`。
