# Role Skill Map

本文件从角色视角维护外部 Skill 的可用能力。角色仍以自身 SOP 和方法论为主，外部 Skill 只作为可调用能力，不替代角色判断。

## UI 设计师

| 场景                                    | 可用 Skill              | 使用方式                                                              |
| --------------------------------------- | ----------------------- | --------------------------------------------------------------------- |
| 高质量 Web 页面、组件、海报、仪表盘设计 | `frontend-design`       | 在 UI/UX 阶段生成视觉方向、信息层级、交互状态和可执行设计约束         |
| 前端实现后界面泛化、审美不稳定          | `frontend-design`       | 在走查阶段给出视觉修正建议和组件级细节                                |
| 已有前端实现需要按 Web 界面规范验收     | `web-design-guidelines` | 将页面或组件代码转成 UI、UX、可访问性问题清单，输出可修复的文件级反馈 |

## 前端工程师

| 场景                                        | 可用 Skill                    | 使用方式                                                                   |
| ------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------- |
| React/Vite/Next.js 实现方案                 | `vercel-react-best-practices` | 在实现前校准组件拆分、状态边界、渲染性能和可维护性                         |
| 复杂 React 组件 API、组合模式或状态边界设计 | `vercel-composition-patterns` | 评估 compound components、Provider 边界、状态提升和 boolean props 膨胀风险 |
| 高设计质量 UI 实现                          | `frontend-design`             | 在实现阶段补足视觉细节、动效、响应式和可访问性约束                         |
| UI 实现完成后的规范化走查                   | `web-design-guidelines`       | 按 Web Interface Guidelines 检查视觉、交互和可访问性，形成修复项           |
| 本地 Web 应用交互验证                       | `webapp-testing`              | 用 Playwright 脚本验证关键用户路径、截图、控制台日志和动态渲染状态         |
| 高风险功能、缺陷修复或行为变更              | `test-driven-development`     | 先写失败测试，再实现最小通过代码，并保留红绿重构证据                       |
| 交付前代码自检                              | `code-review-excellence`      | 在 lint/typecheck/test 之外做结构化代码审查                                |
| 安全相关前端改动                            | `security-review`             | 检查 XSS、敏感信息暴露、权限态、上传下载等风险                             |

## 测试工程师

| 场景                         | 可用 Skill                | 使用方式                                                         |
| ---------------------------- | ------------------------- | ---------------------------------------------------------------- |
| 代码审查反馈转测试策略       | `code-review-excellence`  | 将高风险代码点转成回归用例                                       |
| 安全风险转测试场景           | `security-review`         | 将权限、输入校验和敏感数据风险转成测试点                         |
| UI、UX、可访问性问题转验收项 | `web-design-guidelines`   | 将规范问题转成可复现步骤、预期表现和修复验收标准                 |
| Web 应用端到端回归验证       | `webapp-testing`          | 将关键路径转成 Playwright 自动化脚本，并保留截图、日志和失败证据 |
| 缺陷复现和回归用例先行       | `test-driven-development` | 约束研发先证明测试失败，再用最小实现修复并复测通过               |
| 数据库风险测试设计           | `sql-code-review`         | 将 SQL 注入、索引、N+1、数据一致性和迁移风险转成测试场景         |
| Vue + Pinia 单元测试         | `vue-pinia-unit-test`     | 候选能力，确认技术栈后再安装使用                                 |

## 工程角色通用约束

- `test-driven-development` 只在功能、bugfix、重构或行为变更具备明确可测试边界时使用；输出必须包含失败测试、通过测试和重构后的验证证据。
- `webapp-testing` 只处理可运行 Web 页面或本地服务；输出必须包含脚本、路径、截图/日志或可复现失败证据。
- `web-design-guidelines` 面向已有 UI 实现的规范审查；没有页面、组件或文件上下文时，不替代 `frontend-design` 做创意设计。
- `vercel-composition-patterns` 只用于 React 组件架构和组合模式；普通样式、文案、接口联调不触发。
- `sql-code-review` 只用于 SQL、ORM、schema、索引或迁移上下文；需要真实数据库连接、巡检、工单或慢查询诊断时优先使用本地数据库能力。

## 产品经理

| 场景                                     | 可用 Skill           | 使用方式                                                                   |
| ---------------------------------------- | -------------------- | -------------------------------------------------------------------------- |
| 需求澄清、PRD、roadmap、优先级和验收标准 | `product-management` | 在需求进入 UI/研发前校准目标用户、业务结果、范围裁剪、证据质量和验收口径   |
| 新功能或产品上线需要市场进入策略         | `gtm-strategy`       | 与运营经理协作，检查定位、渠道、发布指标和 launch roadmap 是否支撑产品目标 |

## 运营经理

| 场景                                    | 可用 Skill     | 使用方式                                                        |
| --------------------------------------- | -------------- | --------------------------------------------------------------- |
| GTM、产品发布、活动上线、渠道和用户触达 | `gtm-strategy` | 将产品目标转成上线节奏、渠道策略、messaging、成功指标和复盘口径 |

使用产品/运营外部 Skill 时，需要明确：

- 是否用于 PRD、用户研究、增长实验、指标体系或运营方案。
- 是否会引入业务假设污染，未经证据支持的结论必须标记为假设。
- 输出如何进入需求门禁、运营门禁或上线复盘。
